# 기술 결정 기록 (DECISIONS)

## 1. 엔진 선택: Phaser 3

WebGL 렌더링 전환을 위해 Phaser 3 / PixiJS 중 **Phaser 3**를 선택했다.

- Phaser 3는 타일맵(Tilemap), 씬(Scene) 관리, 카메라, 입력, 파티클 이미터, 트윈(Tween)이
  엔진에 내장되어 있어 "마을 씬" 자체를 별도 프레임워크 조합 없이 빠르게 구성할 수 있다.
- PixiJS는 렌더링 자유도가 더 높지만 타일맵/씬/카메라/충돌을 직접 구현해야 해서,
  남은 작업량(파티클·애니메이션·사운드 훅까지 포함)을 감안하면 Phaser가
  "가장 빠르게 고품질에 도달하는" 선택이다.
- React와의 통합은 `useEffect`로 `Phaser.Game` 인스턴스를 단일 DOM 컨테이너에 마운트하고,
  게임 → React 이벤트는 `Phaser.Events.EventEmitter` 브릿지로 전달하는 방식을 사용한다
  (React 상태/스토어는 그대로 유지, 마을 씬의 렌더링 레이어만 Phaser로 교체).

## 2. "모바일 게임급(3D)" 참고 이미지에 대한 스코프 결정

작업 중 사용자가 첨부한 참고 스크린샷은 풀 3D 렌더링(캐릭터 3D 모델, 리깅, 3D 룸/오브젝트,
실시간 라이팅·반사)을 사용하는 게임이다. 이 수준의 3D를 직접 제작하려면:

- 3D 모델링/리깅 파이프라인(캐릭터, 의상, 가구, 건물 메시 + 텍스처)
- Three.js/Babylon.js 같은 3D 엔진으로의 전면 재작성
- 3D 에셋을 직접 만들거나 구매/다운로드할 수 있는 도구

가 필요하며, 현재 세션에서 사용 가능한 도구(코드 작성/빌드/배포)로는 만들 수 없다.
따라서 이 참고 이미지는 **"3D로 만들어라"가 아니라 "이 정도의 톤·채도·광택·UI 밀도를
2D에서 최대한 구현하라"는 품질 기준**으로 해석했다. 실제로 적용한 것:

- **UI 크롬 글로시화**: 버튼/하단 네비/포인트 배지에 그라데이션 + 상단 광택 하이라이트(`glossy`
  유틸리티 클래스) 적용 — 참고 이미지 우상단의 둥근 사각 아이콘 버튼 톤과 동일한 톤.
- **2D 코지 아트의 입체감 강화**: Phase 5에서 이미 적용한 2단 명암(`shade`/`tint`),
  큰 반짝이는 눈, 볼터치, 바닥 그림자 — 참고 이미지의 부드러운 광원/하이라이트 느낌을 2D로 재현.
- **Phaser 전환(본 문서 1번)**: 동일한 2D 코지 아트를 WebGL 캔버스 위에서 타일맵·카메라·
  파티클과 함께 렌더링하여 "게임처럼 움직이는" 느낌을 강화.

풀 3D 전환은 외부 3D 에셋/모델 제작 리소스가 확보되는 별도 단계에서 재검토할 수 있도록
`docs/redesign-plan.md`에 메모를 남긴다.

## 3. 에셋 출처

Phaser 씬에 사용하는 타일/스프라이트 텍스처는 **외부 에셋 팩을 다운로드할 수 있는 도구가 없어**,
기존 SVG 컴포넌트(Phase 5에서 완성한 `palette.ts` 색상 + `shade()`/`tint()` 명암 규칙)와 동일한
색상·셰이딩 규칙을 적용해 Phaser `Graphics.generateTexture()`로 **코드 내에서 직접 절차적으로
생성**한다. 외부 라이선스 파일이 없으므로 `docs/ASSETS.md`에는 이 생성 방식과 색상 출처
(자체 `palette.ts`)를 기록한다.
